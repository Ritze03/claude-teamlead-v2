# Enforcement

Prose (skills, CLAUDE.md) is for judgment calls; hooks are for invariants — things
that must be true every time, regardless of who is asking or how carefully they
read the instructions. This table is what is actually enforced today, and by
which file. A test (`test.sh`) fails if this table disagrees with the tree: every
file under `hooks/` and `scripts/` appears exactly once below (`hooks/hooks.json`
and `scripts/__pycache__` are the only exclusions).

| File | Hook event / how it runs | What it enforces |
|---|---|---|
| `board-fence.sh` | PreToolUse, matcher `.*board_(add\|update).*` | Only the lead writes the board — any `board_add`/`board_update` from a worker (has `agent_id`) is denied; `board_add` specifically is also denied while a plan is active and its header stage is below 5 (tasks don't belong on the board before the plan's second Go). Reads (`board_list`) are never touched. |
| `gate.sh` | Stop, matcher `*` | Blocks once per turn (guarded by `stop_hook_active`) on: a worker returned but the board still says `running`; board integrity/drift via `board.py check`; a changed tree with no board decomposition; a finished worker's worktree left dirty; during planning (stage ≤ 4) the turn must end on the fixed footer line; at stage 4 the plan itself must pass `plan-lint.sh`; at stage 5 with everything merged, a nudge to bump the header to stage 6; and any task still sitting in `returned` instead of triaged. |
| `lib.sh` | Sourced by `gate.sh`, `record.sh`, `mode.sh`, `plan-fence.sh`, `restore.sh` (not itself an event) | Shared helpers: `tl_init` (reads stdin JSON, no-ops instantly when teamlead is inactive for the project), `tl_json`, `tl_pin_root`, `tl_ensure_gitignore`, `tl_event`, `tl_block`, `tl_now` — the common contract every hook builds on. |
| `mode.sh` | UserPromptSubmit, matcher `*` | Activation/deactivation gated to the exact literal `/teamlead` / `/teamlead stop` prompt (never a phrase appearing elsewhere in a message); while active, records a bare `Go` against the active plan's current stage into `plan-go` (read by `plan-fence.sh`/`gate.sh`/`state.sh`); re-baselines the Decompose gate; re-injects resolved routing names when `settings.md` changes; prints the per-turn open-task/worker reminder. |
| `plan-fence.sh` | PreToolUse, matcher `Edit\|Write\|MultiEdit` | Guards the active plan file's own `> **Stage N**` header: only one stage forward per edit; the 3→4 and 4→5 bumps each require a recorded user "Go" newer than the last accepted bump; `## Notes from me` (the user's inbox) may have a folded line removed by the lead but never added or reworded. |
| `plan-lint.sh` | Not a hook event — called by `gate.sh` at stage 4, by `watch-plan.sh` on every plan-file change, and run manually (`hooks/plan-lint.sh <plan.md>`) | Plan-file consistency: the eight sections present and in canonical order; dependency-wave table entries have a known agent tier and an `After` target that exists in a strictly lower wave; no `Owns` overlap (prefix-aware) within one wave; every `- **D<n>**` decision is referenced by an implementation-plan row once one exists; no inline `> me:` answer left unpromoted under Open questions; no run of 2+ blank lines anywhere; at stage ≥ 4 no `TBD` placeholder in the Goal, no unanswered open questions, no leftover `Notes from me` lines, `Done when` items present with a `verified by: agent\|user` tag on each (and, at stage ≥ 6, an evidence line — `ran \`...\`` — on every ticked agent item); every open question carries a `*Suggest:*`/`*Your call:*` line; the implementation plan is stamped `decisions:<hash>` and that hash matches the current `## Decisions` section. |
| `record.sh` | PreToolUse (matcher `Agent`), SubagentStart, SubagentStop | The ledger writer — the model never writes `events.log` itself. Records a `dispatch` event (with prompt/description) when the lead launches a `tl-*` worker, and a `return` event with the worker's own summary when one stops; ignores non-`tl-*` (harness-internal) agents so the ledger can't be corrupted by unrelated subagents. |
| `resolve.sh` | Not wired in `hooks.json` — called by `mode.sh` whenever `settings.md` is new or changed | Resolves the two routing dials (`effort`, `opus`, `prompting` in `settings.md`) into the actual worker tier names (`work`/`scout`/`esc`/`ceil`/`ban`) for this project, once, instead of leaving the model to re-derive the table on every dispatch. |
| `restore.sh` | SessionStart, matcher `startup\|resume\|clear\|compact` | Puts durable state back after a `/clear`, compaction, or reopening the project (state lived only in context, which gets thrown away); prints the "you are the lead" reminder and the state block; on `clear` with a plan at stage 5–7, adds a note that the plan file and board are the whole handoff. |
| `state.sh` | Not a hook event — called by `mode.sh` (on activation) and `restore.sh` (on session start) | Renders the shared project-state block: whether the project is a git repo, worktree isolation availability, and any worktree currently holding uncommitted work. |
| `statusline.sh` | Not wired in `hooks.json` — installed into the user's own `settings.json` `statusLine` by `install-statusline.sh` | Prints one status-line segment: current mode, open task / working-worker counts, and a `⚠` when `board.py check` reports a problem. Silent whenever teamlead is inactive for the project. |
| `watch-plan.sh` | Not a hook — run via the Monitor tool against a plan file, re-armed by the lead roughly every 30 minutes when it times out | Live-watches the active plan file's directory (not the file itself, since editors save-and-rename) for user edits via inotify; on a real change (not the lead's own last write, matched by content) emits a notification and runs `plan-lint.sh` against the new content. |
| `worktree-fence.sh` | PreToolUse, matcher `Edit\|Write\|MultiEdit` | Confines a `tl-*` worker's file-tool writes to its own `cwd` (the worktree, when isolation is on) — identified by `agent_id`/`agent_type`, so the lead itself (no `agent_id`) is never fenced. |
| `board.py` | CLI (`python3 scripts/board.py <cmd> --project DIR`, used by hooks/tests/humans) and MCP (`board.py --mcp`, the agent's board tool calls) | `board.json` is the single source of truth and `board.md` is a generated rendering — the model never hand-writes the table, so the table can't independently go wrong. Validates every mutation (`add`/`update`) at write time; `check` reports drift/invalid state; `render` regenerates `board.md`; `forget` closes out a worker that will never report back; `ledger`/`status`/`list` summarize outstanding work. |
| `install-statusline.sh` | Run manually (`scripts/install-statusline.sh [--combined\|--only\|--uninstall\|--show]`) | The one setup step teamlead cannot do itself — a plugin can't set the user's main status line — so this writes/backs up/restores `~/.claude/settings.json`'s `statusLine`, asking before replacing anything already configured. |
| `plan-archive.sh` | Run manually (`scripts/plan-archive.sh <plan-file> [--project DIR] [--abandon]`), also invoked by the plan skill at stage 7 completion | Retires a finished plan by datestamping it into `plan/done/` and clearing the active-plan pointer and watcher (never deletes). Refuses a plan with unticked `Done when` boxes unless `--abandon`, which also runs `board.py forget` to close out any workers still outstanding. |
| `statusline-combined.template.sh` | template used by install-statusline.sh | Composite status-line script it stamps out: runs every configured segment (teamlead's plus any others) in parallel with a per-segment timeout and joins whatever they print — adding a segment is one line in its `SEGMENTS` array. |
